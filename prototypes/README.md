# Прототипы экранов MVP мобильного приложения

В разделе представлен черно-белый прототип мобильного приложения, подготовленный для обсуждения логики решения и состава экранов с потенциальным поставщиком.

Прототип не является финальным дизайном интерфейса. Его задача — показать основной пользовательский сценарий, структуру экранов и поведение системы в ключевых ситуациях.

## Основной сценарий

В прототипе отражён следующий пользовательский путь:

**Вход → поиск клиента → открытие карточки или создание нового клиента → добавление комментария → выбор маркетинговых материалов → очередь письма → синхронизация**

Особое внимание уделено работе приложения при нестабильном или отсутствующем интернет-соединении.

## Представленные экраны

В прототипе представлены:

1. Вход в приложение
2. Поиск клиента
3. Результаты поиска
4. Карточка клиента
5. Добавление нового комментария
6. Создание нового клиента
7. Выбор маркетинговых материалов
8. Очередь отправки писем
9. Синхронизация данных

## Что проверяется прототипом

При проектировании экранов проверялись:

- возможность выполнить основной сценарий с мобильного устройства;
- поиск клиента по фамилии, клинике, телефону или электронной почте;
- работа с локальной клиентской базой без интернета;
- понятное отображение офлайн-режима;
- доступ к ключевой информации о клиенте;
- создание нового клиента непосредственно на выставке;
- сохранение комментариев без интернет-соединения;
- выбор маркетинговых материалов;
- постановка письма в очередь при отсутствии связи;
- понятный статус синхронизации данных после восстановления соединения.

## Ключевые ограничения

При создании прототипа учитывались:

- работа до 30 менеджеров;
- необходимость найти и открыть карточку клиента не более чем за 30 секунд;
- обязательная поддержка офлайн-сценария;
- локальное сохранение изменений;
- последующая синхронизация данных;
- возможность работы с большим объёмом маркетинговых материалов без хранения всех файлов на мобильном устройстве.
